# 虚拟环境使用说明

## 🤔 什么是虚拟环境？

虚拟环境就像给每个项目创建一个**独立的房间**，每个房间有自己的Python和依赖包，互不干扰。

### 为什么需要虚拟环境？

**问题场景**：
- 项目A需要 `requests==2.28.0`
- 项目B需要 `requests==2.31.0`
- 如果都装在系统Python里，会冲突！

**解决方案**：
- 项目A有自己的虚拟环境，装 `requests==2.28.0`
- 项目B有自己的虚拟环境，装 `requests==2.31.0`
- 互不干扰 ✅

## 📦 为每个爬虫项目创建虚拟环境

### 方法1：在每个项目文件夹下创建（推荐）

```bash
# 进入项目文件夹
cd 我的爬虫/neuroevolution_book

# 创建虚拟环境
python3 -m venv venv

# 激活虚拟环境（macOS/Linux）
source venv/bin/activate

# 安装依赖
pip install -r requirements.txt

# 运行脚本
python3 scrape_book.py

# 完成后退出虚拟环境
deactivate
```

### 方法2：使用统一的虚拟环境文件夹

```bash
# 在主项目下创建
cd 我的爬虫
python3 -m venv venv

# 激活后安装所有项目的依赖
source venv/bin/activate
pip install -r neuroevolution_book/requirements.txt
pip install -r fudan_faculty/requirements.txt
pip install -r pdf_downloader/requirements.txt
```

## 🎯 推荐做法

**为每个项目创建独立的虚拟环境**，因为：
- ✅ 每个项目的依赖互不干扰
- ✅ 可以同时维护多个项目
- ✅ 删除项目时，虚拟环境一起删除，干净

## 📝 快速操作指南

### 创建虚拟环境

```bash
# 进入项目
cd 我的爬虫/neuroevolution_book

# 创建虚拟环境
python3 -m venv venv
```

### 激活虚拟环境

```bash
# macOS/Linux
source venv/bin/activate

# Windows
venv\Scripts\activate
```

激活后，命令行前面会显示 `(venv)`，表示已激活。

### 安装依赖

```bash
pip install -r requirements.txt
```

### 运行脚本

```bash
python3 scrape_book.py
```

### 退出虚拟环境

```bash
deactivate
```

## 🔍 检查是否在虚拟环境中

```bash
# 方法1：看命令行前缀
# 如果有 (venv) 前缀，说明已激活

# 方法2：检查Python路径
which python3
# 如果在虚拟环境中，路径会是：.../venv/bin/python3
# 如果不在，路径是：/usr/bin/python3 或 /Library/.../python3
```

## ⚠️ 注意事项

1. **每次运行脚本前都要激活虚拟环境**
2. **虚拟环境文件夹（venv/）不要提交到Git**
3. **如果项目删除，虚拟环境文件夹也要删除**
